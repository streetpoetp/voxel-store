# Spec Delta

## MODIFIED Requirements

### Requirement: Store domain roots reflect current authority
The active repository layout SHALL separate reusable Assets, Styles, Collections, Store policy/history, and derived Catalog outputs. Product discovery SHALL remain restricted to Assets. Model-owned sockets/Mount and metadata remain physical compatibility authority. Store policy owns reusable visual animation profiles; asset manifests choose applicable profiles and model source owns curves.

#### Scenario: Model-owned compatibility metadata changes
- **WHEN** an avatar socket contract or equipment attachment metadata changes
- **THEN** compatibility and health derive the physical result from current model-owned inputs independently of collection policy

#### Scenario: Animation profile policy changes
- **WHEN** an applicable motion family or coverage rule changes
- **THEN** Tool derives new validation and proof requirements from current policy and each asset's selected profile, without treating derived catalog or Unity as policy authority

## ADDED Requirements

### Requirement: Explicit animation migration converges existing catalog through bounded asset jobs
An approved catalog animation migration SHALL upgrade all current models through the canonical one-asset pipeline, preserving geometry, identity, palette, VPU, pivots and physical attachment frames. It SHALL retain normal maintenance's one-job boundary and require current evidence before reporting completion.

#### Scenario: Catalog migration is authorized
- **WHEN** the existing eleven avatars and fourteen equipment assets adopt the new profile policy
- **THEN** each asset receives applicable authored families and four distinct takes per family with no irrelevant aliases, and the migration reports each asset's current gate

#### Scenario: Selected asset cannot pass a gate
- **WHEN** a migrated asset has invalid source or missing graphical acceptance
- **THEN** the job remains blocked at that gate rather than skipping or resealing stale proof to claim migration success

#### Scenario: Catalog migration completes
- **WHEN** all twenty-five assets satisfy current source, generation, visual proof, compatibility, seals and coverage
- **THEN** scan and verify report every asset published, Healthy true and NextJob null, with normal maintenance returning a healthy no-op
